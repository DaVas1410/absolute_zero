# Conversaciones con especialistas — Simuladas

Estas conversaciones son intencionalmente informales. El sistema debe poder distinguir afirmaciones, opiniones y datos que requieren validación.

## Conversación A — Especialista de datos
**Pregunta:** ¿Tenemos experiencia integrando muchas fuentes?
**Respuesta:** Sí. En el caso Nimbus se integraron 18 fuentes. Aurora Bank tuvo 9 fuentes. Para AndesFin habría que revisar cuántas fuentes existen realmente antes de comprometer una arquitectura.

## Conversación B — Especialista cloud
**Pregunta:** ¿Podemos trabajar con Azure?
**Respuesta:** El catálogo incluye Azure y el equipo tiene un perfil de arquitectura cloud. Sin embargo, el dataset no contiene un proyecto donde Azure sea el proveedor principal y financiero al mismo tiempo. Conviene expresarlo con cautela.

## Conversación C — Especialista de seguridad
**Pregunta:** ¿Podemos afirmar que tenemos certificación PCI-DSS?
**Respuesta:** No. No hay evidencia en el material simulado. Debe marcarse como requisito pendiente de validación.

## Conversación D — Especialista de delivery
**Pregunta:** ¿Cuánto tardaría un piloto?
**Respuesta:** La metodología usa como referencia 6–8 semanas para un piloto. Es una referencia, no un compromiso.

## Conversación E — Especialista comercial
**Pregunta:** ¿Debemos incluir todos nuestros casos?
**Respuesta:** No. Lo recomendable es seleccionar evidencias que respondan directamente a los requisitos del cliente y explicar la relación.
